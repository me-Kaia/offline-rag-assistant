# 架构说明

整个应用是一个 `index.html` 文件：CSS 负责样式，HTML 负责页面结构，JavaScript 负责全部逻辑。JavaScript 分为四层。

| 层 | 主要函数 | 作用 |
| --- | --- | --- |
| Ollama 接口 | `api()` `checkOllama()` `embed()` `streamChat()` | 与本机 Ollama 的 HTTP 接口通信 |
| 资料库 | `chunkFile()` `addFiles()` `retrieve()` `cos()` | 分块、向量化、存储、检索 |
| 显示 | `md()` `addMsg()` `finish()` | 把模型输出的 Markdown 渲染为网页 |
| 发送 | `send()` | 串联以上各层，完成一次问答 |

程序有两条主线：**添加文件** 和 **提问**。

## 一、添加文件

### 1. 分块 `chunkFile()`

```js
for (const part of text.split(/\n(?=##\s)/)) { ... }
```

正则 `/\n(?=##\s)/` 表示在每个以 `## ` 开头的行前切分，因此每个二级标题章节成为一块。超过 900 字的章节继续切分，每次前进 800 字，相邻两块重叠 100 字，防止关键句子被切断。

每块前面加上文档标题 `【标题】`，这样即使某块只包含"D4 根本原因"，检索时也知道它属于哪份报告。

### 2. 向量化 `embed()`

调用 Ollama 的 `POST /api/embed`，模型为 `bge-m3`。每次批量发送 8 块以减少请求次数，每块返回一个 1024 维向量。

### 3. 存储

文件原文、分块文本和向量一起存入 `localStorage`。向量保留 5 位小数以节省空间。重新打开页面时直接读取，无需重新计算。

## 二、提问（查资料模式）

### 1. 检索 `retrieve()`

把问题本身也用 bge-m3 转成向量，然后与资料库中每一块计算余弦相似度：

```js
function cos(a, b){
  let d = 0, na = 0, nb = 0;
  for (let i = 0; i < a.length; i++){ d += a[i]*b[i]; na += a[i]*a[i]; nb += b[i]*b[i]; }
  return d / (Math.sqrt(na * nb) || 1);
}
```

即两向量点积除以各自长度的乘积，结果越接近 1 表示语义越接近。按分数排序取前 4 块。资料量在几百块以内时，这种暴力计算在浏览器里只需几毫秒，不需要专门的向量数据库。

### 2. 拼接提示词

检索到的段落按 `[资料1] 来自《文件名》` 的格式拼在问题前面，连同系统提示词一起发给模型。系统提示词要求模型只根据资料回答、注明文件编号、资料中没有就直接说明，以减少编造。

### 3. 生成 `streamChat()`

调用 `POST /api/chat`，设置 `stream: true`。Ollama 以 NDJSON 格式（每行一个 JSON）逐段返回生成内容，程序用 `ReadableStream` 逐行解析并实时渲染，所以回答是一个字一个字出现的。请求中设置 `num_ctx: 8192` 扩大上下文窗口，`temperature: 0.3` 让回答更稳定。

用户点击"停止"时，通过 `AbortController` 中断请求。

### 4. 显示来源

回答结束后，在下方列出本次检索命中的文件名。

## 三、其他模式

- **质量周报**：不走检索，直接把文件名含 `8D` 的全部报告原文交给模型，按固定表格格式汇总。因为周报需要每份报告的完整信息，检索 Top 4 容易遗漏。
- **自由对话**：不查资料库，保留最近 6 条对话历史，用于写邮件、翻译等。

## 四、为什么页面能访问 Ollama

浏览器出于安全限制，默认不允许本地 HTML 文件请求其他地址的服务（跨域）。Ollama 通过环境变量 `OLLAMA_ORIGINS` 控制允许的来源，设为 `*` 后本机网页即可访问。Ollama 默认只监听 `127.0.0.1`，局域网中的其他设备仍无法访问。
